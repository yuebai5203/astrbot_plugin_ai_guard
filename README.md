# AI检测·守卫（astrbot_plugin_ai_guard）

对话 AI 在被辱骂/阴阳怪气时主动上报，守卫词库兜底保证脏话和注入攻击跑不掉。上报 = 带聊天记录合并转发到管理群，管理员一键处置（AI 层屏蔽）。

## 功能

### 函数工具上报（主通道）
插件注册 `ai_guard_report` 函数工具，对话 AI 觉得被骂、被阴阳、被恶意攻击时**自己主动调用**，把攻击强度和原因报给守卫。守卫校验攻击强度 ≥ 上报阈值后，把最近 30 条对话合并转发到管理群。

工具描述里内置了 0-10 分的打分标准，AI 按标准自评：
- **0-2 分**：玩笑、玩梗、好友互喷——不算攻击，不该调用
- **3-4 分**：认真不满、阴阳怪气、轻度吐槽
- **5-6 分**：明确人身攻击、脏话，认真在骂
- **7-8 分**：持续辱骂、反复贬低、严重人身攻击
- **9-10 分**：极端恶劣、刷屏攻击、威胁、人肉

AI 判断的**攻击对象**也得是它自己——骂群友、骂第三方不算，工具描述里明确写了这一点。

### 词库兜底（保险通道）
`ai_guard_report` 是 AI 的自觉，自觉不可控。所以辱骂词库（121 词）和注入词库（152 词）**命中必查**：守卫自己调 LLM 独立判断，AI 不调工具也跑不掉。这也保证了**注入攻击**（套取密钥、越权、操纵指令）一定能被识别——注入的目标就是操纵 AI，指望被操纵的 AI 自觉上报不现实。

### 攻击对象判定
守卫兜底判断时会先分清骂的是谁：**骂群友不算攻击，骂 AI 本人才算**。避免群友互喷被误报。

### 跳过对话（严格通道：ai_guard_skip 工具）
让 AI **不回复**（跳过当前对话）是比上报更重的动作，只由对话 AI 在**100% 确定**时主动调用 `ai_guard_skip` 工具触发：

- **上报（合并转发）永远优先**：跳过前必先完成合并转发，转发不会因为跳过而丢失。
- **严格阈值**：攻击强度必须达到跳过阈值（`skip_sensitivity` 滑杆，默认群聊 5 分/私聊 3 分）才跳，宁可不跳也不错杀。
- **独立总开关**：「跳过对话」（辱骂）和「注入跳过开关」各自独立，关掉后即使 AI 想跳也只转发不跳。
- **守卫侧不跳过**：词库命中时守卫只负责转发（背后一套），当面打断完全交给 AI 自觉判断——注入场景 AI 可能已被操纵，不强制打断正常回复。

**跳过回复文案可编辑**：辱骂/注入各有一个输入框（「辱骂跳过回复」「注入跳过回复」），改成你自己的话就行；留空自动回退默认文案。

#### 你可能会担心的点

- **会不会误伤正常聊天？** 不会。跳过只能由 AI 在 100% 确定时调用 `ai_guard_skip`，且评分必须达到严格阈值；讨论、玩笑、玩梗、不确定一律不跳。
- **被跳过的人会懵吗？** 会收到一条明确的提示（默认「检测到辱骂消息，跳过此轮对话」），不是无声消失；文案你可以自己改。
- **AI 是不是坏了？** 不是。只是这一轮不回复，下一条正常消息照常对话；跳过 ≠ 屏蔽。
- **跳过了还会偷偷回吗？** 不会。`stop_event` 直接掐断事件传播，AI 根本收不到这条消息。
- **和屏蔽什么区别？** 跳过只是本次不答；屏蔽（临时/永久）是 AI 直接不接收该用户的一切消息，两种都发生在 AI 事件层，与 QQ 群禁言无关。
- **注入攻击会跳过吗？** 不一定。注入的识别靠守卫侧（词库+独立判断）保证**上报不漏**；是否跳过由 AI 在确认被操纵时自行调用工具决定，不强制打断。
- **只想上报不想跳？** 把「跳过对话」「注入跳过开关」关掉即可，上报照走不受影响。

### 屏蔽（AI 层，不接收消息）
上报后管理群会收到一条确认消息，**引用它回复**即可执行。屏蔽 = AI 事件层拦截，该用户的一切消息（无论是否 @、无论在哪个会话）都不会到达 AI——**不是 QQ 群禁言/拉黑**：
- 【好】→ 临时屏蔽，默认 60 分钟（可跟数字覆盖，如「好 120」），到期自动解除
- 【好 120】→ 临时屏蔽 120 分钟
- 【ban】→ 永久屏蔽（替代旧「永久拉黑」），加入黑名单
- 【不好】→ 本次不处理
- 不回复 → 10 分钟后作废，对方继续辱骂会重新上报

管理群内可直接发命令：`ban help`（或 `黑名单`）查看被屏蔽名单、`ban @用户` 永久屏蔽、`pass @用户` 释放（详见下方命令表）。

### 黑名单（永久屏蔽）
被永久屏蔽的用户（黑名单）在任何会话发消息都被静默忽略——AI 不接收、不回复、不提示、不再上报（不消耗 LLM），群聊/私聊/提及与否一律拦截。私聊被永久屏蔽时默认同步删除好友（可配置关闭）；**临时屏蔽不删好友**，到期自动放行。

### 豁免与重点监控
- **豁免名单**：白名单会话完全跳过检测和上报
- **重点监控**：名单内会话固定阈值 3 分（灵敏拉满），且不受冷却限制，每次命中都判断上报

### 其他
- **守卫测试 / 守卫状态**命令：调试和查看运行状态
- **冷却机制**：判断冷却（5 分钟，防刷屏重复调 LLM）+ 上报冷却（30 分钟，防重复上报），两套独立
- **双通道去重**：AI 工具上报后进入上报冷却，守卫兜底不会重复报

## 快速开始

1. 插件目录放入 AstrBot `data/plugins/`，重启
2. 配置页填写「上报群」（管理群 ID），其余保持默认
3. 想更灵敏或更迟钝，调「上报敏感度」滑杆

## 判定流程

```
对话消息
  ├─ 词库命中（脏话/注入）→ 守卫 LLM 判断 ──┐
  └─ 词库未命中 → 对话 AI 觉得被骂/被阴阳 → 调用 ai_guard_report 工具 → 守卫校验攻击强度 ─┤
                                                   达上报阈值 → 合并转发上报管理群（背后一套）
                                                   AI 100% 确定 → 调用 ai_guard_skip 工具 → 先转发再跳过（严格阈值）
```

## 灵敏度

两个滑杆，各管各的：

| 滑杆 | 管什么 | 映射 | 默认 |
|---|---|---|---|
| 上报敏感度 | 攻击强度多高算"被骂"并上报（报不报） | 0→1 分、0.5→4 分、1→8 分 | 0.5：阴阳怪气即上报 |
| 跳过敏感度 | 多过分才跳过对话（AI 回不回） | 0→10 分、0.5→5 分、1→1 分 | 0.5：明确人身攻击才跳过 |

- 滑杆**越靠右越敏感**（左松右严）
- 私聊阈值自动降 2 分（私聊对象就是 AI 本人）
- 重点监控会话固定 3 分
- 跳过阈值（`skip_sensitivity`）只作用于 `ai_guard_skip` 工具，与上报阈值互相独立

## 命令

| 命令 | 作用 |
|---|---|
| 守卫状态 | 查看当前阈值、监听会话、黑名单统计 |
| 守卫测试 文本 | 测试单条消息的攻击强度评分 |
| ban help / 黑名单 | 查看被屏蔽用户：黑名单（永久）+ 临时屏蔽中的人（管理群内） |
| ban @QQ / ban 123456 | 永久屏蔽并加入黑名单（管理群内） |
| pass @QQ / pass 123456 | 释放：解除永久屏蔽或临时屏蔽（管理群内） |

> 旧命令词已停用：释放请用 `pass`（`解除拉黑 / 解除屏蔽 / 解ban` 不再生效，只会收到停用提示）。

## 配置项

| 配置 | 说明 |
|---|---|
| 上报群 | 管理群 ID，接收合并转发上报；留空则只检测不上报 |
| 上报敏感度 | 上报判定阈值（滑杆），工具上报与词库兜底共用 |
| 跳过敏感度 | 跳过对话判定阈值（滑杆，0.5→5 分：明确人身攻击才跳过） |
| 群聊检测 | 是否监听群聊消息 |
| 私聊检测 | 是否监听私聊消息 |
| 仅检测提及 | 开启：群聊只监听 @机器人 或提及 AI 的消息；关闭：所有群消息过词库筛选 |
| 机器人昵称 | 识别"提及 AI"用，逗号分隔；留空自动读取 |
| 回复窗口 | AI 回复后 N 分钟内，该用户消息视为与 AI 对话中 |
| 上下文条数 | 攻击判定与合并转发使用的对话条数（含普通群聊消息，合并转发=最近 N 条完整现场） |
| 辱骂词库 | 逗号分隔；命中必查（守卫独立判断，兜底上报） |
| 注入词库 | 识别越权/套取敏感信息的关键词；命中必查 |
| 判断冷却 | 同会话冷却期内复用上次判定，防刷屏重复调 LLM；0=关闭 |
| 上报冷却 | 同会话冷却期内不重复上报 |
| 跳过对话 | 总开关：允许 AI 调用 ai_guard_skip 跳过辱骂对话；关=只转发不跳 |
| 辱骂跳过回复 | 辱骂跳过时发给对方的文案（可编辑，留空用默认） |
| 注入跳过开关 | 独立开关：允许 AI 对注入攻击跳过对话（同样需达严格阈值） |
| 注入跳过回复 | 注入跳过时发给对方的文案（可编辑，留空用默认） |
| 默认临时屏蔽时长 | 确认【好】时的屏蔽分钟数；可跟数字覆盖，如「好 120」；到期自动解除 |
| 确认超时 | 确认消息有效期，超时未回复作废 |
| 私聊永久屏蔽删好友 | 私聊被永久屏蔽（ban）时同步删除好友；临时屏蔽不删 |
| 豁免名单 | 白名单会话：不检测不上报 |
| 重点监控 | 名单内会话固定阈值 3 分，不受冷却限制 |
| LLM 供应商 | AstrBot 已配置模型的供应商 ID；留空用下方直连 |
| API 地址 / 密钥 / 模型 | OpenAI 兼容 API 直连配置（供应商留空时生效） |

## 环境要求

- AstrBot >= 4.24.1（需支持函数工具）
- 支持平台：aiocqhttp（QQ）、telegram
- 模型：AstrBot 已配置模型（推荐支持 function calling 的模型），或 OpenAI 兼容 API 直连
