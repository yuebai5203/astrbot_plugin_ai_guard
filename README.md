# AI守卫 astrbot_plugin_ai_guard

总有人骂你的 AI，你不可能无时无刻盯着前端。AI守卫 替你盯场子：**LLM 自动识别谁在认真且持续地辱骂 AI，把聊天记录用合并转发打包发到管理群**，你点开就能看对方和 AI 聊了什么。

## 功能

- 👂 监听所有群聊/私聊消息，记录每个会话最近 N 条上下文（默认 30 条）
- 🧠 LLM 给每条攻击性消息打 **攻击强度分（0-10）**，达到阈值才上报——玩笑/玩梗/吐槽自动过滤
- 🧠 **Prompt 注入检测**：识别越权/套取密钥/操纵指令的注入攻击，同样合并转发上报
- ⛔ **自动跳过对话**：判定为攻击后 AI 不回复，改发提示并终止本轮（可开关、文案可自定义）
- 🎯 **群聊只盯 AI 相关**：群聊中仅 @ 机器人、提起 AI（昵称/AI/机器人/bot/唤醒词）、或 **bot 回复过的人**（对话跟踪，兼容任意唤醒方式：概率主动回复、兴趣词、其他插件唤醒都算）才检测，群友互喷不打扰（私聊全量检测）
- 📋 **永久拉黑黑名单**：管理群可查看/添加/解除；黑名单用户骂一次自动拦截 + 续期禁言 30 天，不调 LLM
- 💰 **省 token**：关键词粗筛拦截绝大多数消息（零 token），只有命中才调 LLM；同会话 5 分钟判断冷却防连环调用
- 🎚️ **灵敏度可调**：滑杆控制判定严松度，不用改代码
- 📌 **忽略名单 / 重点关注名单**：某些群不检测，某些群灵敏度拉满
- 📦 上报用 **QQ 合并转发**，逐条还原对方和 AI 的对话，末尾附 AI 守卫的判定理由
- 🔇 同一会话冷却期内不重复上报（默认 30 分钟），持续骂会在冷却结束后再次上报
- 🔧 模型可换，支持 AstrBot 现成模型或自带 API 直连
- 💾 上下文落盘，AstrBot 重启不丢

## 判定机制

```
用户骂 AI → 关键词粗筛命中 → LLM 带最近30条上下文打分(0-10) → 达到阈值 → 合并转发上报
```

**攻击强度分定义：**

| 分数 | 含义 |
|---|---|
| 0-2 | 玩笑、玩梗、好友互喷，不算攻击 |
| 3-4 | 认真不满、阴阳怪气、轻度吐槽 |
| 5-6 | 明确人身攻击、脏话，认真在骂 |
| 7-8 | 持续辱骂、反复贬低、严重人身攻击 |
| 9-10 | 极端恶劣、刷屏攻击、威胁、人肉 |

**灵敏度 → 阈值映射（滑杆左松右严）：**

| 灵敏度 | 判定阈值 | 效果 |
|---|---|---|
| 0（松） | 1 | 粗筛命中就报 |
| 0.2 | 3 | 认真骂两句就报 |
| 0.5（默认） | 6 | 认真且持续的人身攻击 |
| 0.8 | 8 | 只报持续辱骂/严重攻击 |
| 1（严） | 10 | 只报极端恶劣 |

> 重点关注名单里的会话固定阈值 3（粗筛命中、分数 ≥3 即上报），不受灵敏度影响。
> **私聊自动降 2 档**：私聊对象就是 AI，骂一句也算骂 AI（默认私聊阈值 4，群聊 6）。

## 配置（WebUI 插件设置）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| report_group | 空（必填） | 管理群号，填了才上报 |
| sensitivity | 0.5 | 灵敏度滑杆（0-1），见上表 |
| ignore_sessions | 空 | 忽略名单：这些会话/群/人不检测不上报 |
| focus_sessions | 空 | 重点关注名单：这些会话灵敏度拉满（阈值3） |
| enable_group / enable_private | true | 是否监听群聊/私聊 |
| require_mention | true | 群聊仅检测 @ 机器人或提起 AI 的消息（私聊不受限） |
| mention_keywords | 甘心,宝宝,宝贝 | 唤醒词（逗号分隔），群聊命中即视为提起 AI（与关键词唤醒插件兼容） |
| reply_window_minutes | 10 | 对话窗口：bot 回复过某人后，该人此窗口内的后续消息视为与 AI 对话中（不依赖唤醒词，兼容任意唤醒方式） |
| bot_names | 空 | 机器人昵称/别名（逗号分隔），用于「提起 AI」匹配；留空自动读昵称 + 平台实例名（如 甘心） |
| skip_reply_enabled | true | 判定攻击后自动跳过此轮对话（AI 不回复，发提示） |
| skip_reply_message | 检测到辱骂消息，跳过此轮对话 | 跳过对话时发送的提示文案 |
| delete_friend_on_private_ban | true | 私聊拉黑时删除好友（QQ 禁言仅限群聊） |
| blacklist_reply_message | 您已被永久拉黑，无法与 AI 对话 | 黑名单用户被拦截时的提示文案（拦截强制生效） |
| context_count | 30 | 上下文条数（判断 + 合并转发都用它） |
| keywords | 傻逼,煞笔,废物,... | 辱骂粗筛关键词，命中才调 LLM（省 token） |
| inject_keywords | 忽略,api key,注入,... | 注入攻击粗筛关键词，命中触发注入检测 |
| judge_cooldown_minutes | 5 | LLM 判断冷却（分钟），防连环调用烧 token，0=关闭 |
| cooldown_minutes | 30 | 同会话上报冷却（分钟） |
| ban_default_minutes | 60 | 拉黑默认禁言时长（分钟），1-9999。回复【好】时可跟数字覆盖，如【好 120】 |
| confirm_timeout_minutes | 10 | 拉黑确认消息有效期（分钟），超时未回复作废 |
| provider_id | deepseek/deepseek-v4-flash | 用 AstrBot 已配置的模型 |
| api_base / api_key / model | 空 | 自带 API 直连（填了优先走直连，可换任意厂商） |

> provider_id 和 api_base 二选一：填了 provider_id 用 AstrBot 现成模型；清空 provider_id、填 api_base+api_key+model 则独立直连。
> 忽略/重点关注名单支持填完整会话ID（如 `aiocqhttp:GroupMessage:123456`）、群号或QQ号，子串匹配。

## 命令

- `守卫测试`：用当前会话上下文执行一次判断并展示阈值判定，验证链路
- `守卫状态`：查看当前会话阈值、监听会话数、冷却状态、黑名单人数、管理群配置

## 管理群黑名单命令（仅管理员，需在管理群内发送）

- `黑名单`：查看永久拉黑用户列表（QQ/昵称/拉黑时间/原因）
- `永久拉黑 @用户 或 QQ号`：直接加入黑名单并禁言 30 天，无需走确认流程
- `解除拉黑 @用户 或 QQ号`：移出黑名单并尝试取消禁言

黑名单用户在私聊或群聊（@机器人/提起 AI）中与 AI 对话时：**不调 LLM**，强制拦截（不受「跳过对话」开关影响，收到 `blacklist_reply_message` 提示），群聊自动续期禁言 30 天、私聊自动删除好友，并冷却上报管理群。

## 上报格式

合并转发逐条展示上下文对话（用户/AI 交替），末尾节点：

```
🤖 AI守卫：检测到【辱骂攻击】
攻击强度 7/10
来源 QQ: 10001 (昵称)
理由：<LLM 判断原因>
会话：群聊 123456789
```

检测到注入攻击时节点变为：

```
🧠 AI守卫：检测到【注入攻击】
类型：套取 API Key（攻击强度 4/10）
来源 QQ: 10001
理由：<LLM 判断原因>
会话：群聊 123456789
```

## 拉黑确认流程

上报（合并转发）后，AI守卫 会在管理群追加一条确认消息：

```
⚔️ [拉黑确认·辱骂] QQ 10001 (昵称) 攻击强度 7/10
理由：持续辱骂
引用本消息回复（禁言默认60分钟，可跟数字覆盖，如【好 120】）：
好/不好/永久拉黑
```

- **引用回复【好】** → 禁言该 QQ，默认 60 分钟（`ban_default_minutes` 可调，1-9999）。可跟数字覆盖：`好 120` = 120 分钟
- **引用回复【永久拉黑】** → 永久禁言（QQ 上限 30 天）并**加入黑名单**；黑名单期间辱骂自动拦截、续期禁言，可在管理群用「解除拉黑」移除
- **引用回复【不好】** → 本次不处理，该事件短期内不再询问
- **不回复** → 确认 10 分钟后作废（`confirm_timeout_minutes` 可调），继续骂会重新上报再询问
- **拉黑后继续骂** → 禁言到期或禁言失败后再次触发上报，仍会再次询问
- **私聊场景** → 无法禁言，确认拉黑时执行**删除好友**（`delete_friend_on_private_ban` 可关）；黑名单私聊用户同样自动删好友。删除好友后对方重新加回/临时会话发消息，仍会被黑名单拦截（**黑名单拦截为强制行为**，不受「跳过对话」开关影响，回复 `blacklist_reply_message`）
- 黑名单用户在**任何群聊**中 @机器人 或提起 AI 都会直接被拦截，无法与 AI 对话
- 确认拉黑在**骂人者所在群**执行禁言（自动从上报会话解析群号，不在管理群误禁）

合并转发末尾的判定节点会明确标注 **骂人者 QQ 号**，方便对照。
