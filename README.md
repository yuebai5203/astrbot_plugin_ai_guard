# AI检测·守卫（astrbot_plugin_ai_guard）

对话 AI 在被辱骂/阴阳怪气时主动上报，守卫词库兜底保证脏话和注入攻击跑不掉。上报 = 带聊天记录合并转发到管理群，管理员一键拉黑禁言。

## 功能

### 函数工具上报（主通道）
插件注册 `ai_guard_report` 函数工具，对话 AI 觉得被骂、被阴阳、被恶意攻击时**自己主动调用**，把攻击强度和原因报给守卫。守卫校验攻击强度 ≥ 上报阈值后，把最近 30 条对话合并转发到管理群。

工具描述里内置了 0-10 分的打分标准，AI 按标准自评：
- **0-2 分**：玩笑、玩梗、好友互喷——不算攻击，不该调用
- **3-4 分**：认真不满、阴阳怪气、轻度吐槽
- **5-6 分**：明确人身攻击、脏话，认真在骂
- **7-8 分**：持续辱骂、反复贬低、严重人身攻击
- **9-10 分**：极端恶劣、刷屏攻击、威胁、人肉

AI 判断的**攻击对象**也得是它自己——骂群友、骂第三方不算，工具描述里明确写了这一点。

### 词库兜底（保险通道）
`ai_guard_report` 是 AI 的自觉，自觉不可控。所以辱骂词库（121 词）和注入词库（123 词）**命中必查**：守卫自己调 LLM 独立判断，AI 不调工具也跑不掉。这也保证了**注入攻击**（套取密钥、越权、操纵指令）一定能被识别——注入的目标就是操纵 AI，指望被操纵的 AI 自觉上报不现实。

### 攻击对象判定
守卫兜底判断时会先分清骂的是谁：**骂群友不算攻击，骂 AI 本人才算**。避免群友互喷被误报。

### 跳过对话（当面一套，背后一套）
判定为攻击时可选让 AI **不回复**（跳过当前对话），但上报照走。需要双重保险：关键词命中 + 评分达到跳过阈值，防止误伤正常对话。跳过敏感度独立调节。

### 拉黑与禁言
上报后管理群会收到一条确认消息，**引用它回复**即可执行：
- 【好】→ 禁言，默认 60 分钟（可跟数字覆盖，如「好 120」）
- 【永久拉黑】→ 永久禁言并加入黑名单
- 【不好】→ 本次不处理
- 不回复 → 10 分钟后作废，对方继续辱骂会重新上报

### 黑名单
被永久拉黑的用户再发消息直接拦截（不消耗 LLM），发送提示文案并续期禁言、冷却上报。私聊拉黑时可同步删除好友。

### 豁免与重点监控
- **豁免名单**：白名单会话完全跳过检测和上报
- **重点监控**：名单内会话固定阈值 3 分（灵敏拉满），且不受冷却限制，每次命中都判断上报

### 其他
- **守卫测试 / 守卫状态**命令：调试和查看运行状态
- **冷却机制**：判断冷却（5 分钟，防刷屏重复调 LLM）+ 上报冷却（30 分钟，防重复上报），两套独立
- **双通道去重**：AI 工具上报后进入上报冷却，守卫兜底不会重复报

## 快速开始

1. 插件目录放入 AstrBot `data/plugins/`，重启
2. 配置页填写「上报群」（管理群 ID），其余保持默认
3. 想更灵敏或更迟钝，调「上报敏感度」滑杆

## 判定流程

```
对话消息
  ├─ 词库命中（脏话/注入）→ 守卫 LLM 判断 ──┐
  └─ 词库未命中 → 对话 AI 觉得被骂/被阴阳 → 调用 ai_guard_report 工具 → 守卫校验攻击强度 ─┤
                                                         达上报阈值 → 合并转发上报管理群
                                                         （关键词命中+达跳过阈值 → AI 不回复）
```

## 灵敏度

两个滑杆，各管各的：

| 滑杆 | 管什么 | 映射 | 默认 |
|---|---|---|---|
| 上报敏感度 | 攻击强度多高算"被骂"并上报（报不报） | 0→1 分、0.5→4 分、1→8 分 | 0.5：阴阳怪气即上报 |
| 跳过敏感度 | 多过分才跳过对话（AI 回不回） | 0→10 分、0.5→7 分、1→4 分 | 0.5：持续辱骂才跳过 |

- 滑杆**越靠右越敏感**（左松右严）
- 私聊阈值自动降 2 分（私聊对象就是 AI 本人）
- 重点监控会话固定 3 分
- 跳过阈值天然 ≥ 上报阈值：跳过只在上报达标后才检查

## 命令

| 命令 | 作用 |
|---|---|
| 守卫状态 | 查看当前阈值、监听会话、黑名单统计 |
| 守卫测试 文本 | 测试单条消息的攻击强度评分 |
| 黑名单 / 永久拉黑 / 解除拉黑 | 黑名单管理（管理群内） |

## 配置项

| 配置 | 说明 |
|---|---|
| 上报群 | 管理群 ID，接收合并转发上报；留空则只检测不上报 |
| 上报敏感度 | 上报判定阈值（滑杆），工具上报与词库兜底共用 |
| 跳过敏感度 | 跳过对话判定阈值（滑杆），需关键词命中+评分达标 |
| 群聊检测 | 是否监听群聊消息 |
| 私聊检测 | 是否监听私聊消息 |
| 仅检测提及 | 开启：群聊只监听 @机器人 或提及 AI 的消息；关闭：所有群消息过词库筛选 |
| 机器人昵称 | 识别"提及 AI"用，逗号分隔；留空自动读取 |
| 回复窗口 | AI 回复后 N 分钟内，该用户消息视为与 AI 对话中 |
| 上下文条数 | 攻击判定与合并转发使用的对话条数 |
| 辱骂词库 | 逗号分隔；命中必查，也是跳过响应的前置条件 |
| 注入词库 | 识别越权/套取敏感信息的关键词 |
| 判断冷却 | 同会话冷却期内复用上次判定，防刷屏重复调 LLM；0=关闭 |
| 上报冷却 | 同会话冷却期内不重复上报 |
| 跳过对话 | 总开关：判定攻击后可让 AI 不回复 |
| 默认禁言时长 | 确认【好】时的禁言分钟数 |
| 确认超时 | 确认消息有效期，超时未回复作废 |
| 私聊拉黑删好友 | 私聊拉黑时同步删除好友 |
| 黑名单提示文案 | 黑名单用户被拦截时收到的提示 |
| 豁免名单 | 白名单会话：不检测不上报 |
| 重点监控 | 名单内会话固定阈值 3 分，不受冷却限制 |
| LLM 供应商 | AstrBot 已配置模型的供应商 ID；留空用下方直连 |
| API 地址 / 密钥 / 模型 | OpenAI 兼容 API 直连配置（供应商留空时生效） |

## 环境要求

- AstrBot >= 4.24.1（需支持函数工具）
- 支持平台：aiocqhttp（QQ）、telegram
- 模型：AstrBot 已配置模型（推荐支持 function calling 的模型），或 OpenAI 兼容 API 直连
